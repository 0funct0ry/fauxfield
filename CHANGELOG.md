# Changelog

## Unreleased

### Added
- Example workspaces (M19.1): `fauxfield init [PATH] --example <name>` creates one of ten ready-to-run multi-Server Workspaces embedded in the binary (`ecommerce`, `banking`, `social`, `food-delivery`, `ride-hailing`, `saas-billing`, `healthcare`, `iot-fleet`, `streaming-media`, `travel-booking`), each with 6 Servers on ports 4001 to 4006, CRUD Routes on seeded generator Datasets, Rules, Callbacks or WebSockets where they fit, a `local` and `staging` Environment and a `docs/README.md` with curl commands. `--list-examples` (`--json`), `--force-example`; unknown names exit 2 with a hint. Command Palette: *Workspace: New from Example…* and *Add Example to This Workspace…* (both choose the example from a list; with a Workspace open the example is added to it, otherwise a folder is asked for) and *List Examples*; MCP tools `list_examples` and `init_workspace`. Sources live in `examples/` (generated by `cargo xtask examples`); new guide *Example Workspaces*.
- Distribution and release (M19): cargo-dist configuration (`dist-workspace.toml`, generated `release.yml`) for macOS, Linux and Windows archives, shell and PowerShell installers, MSI and the Homebrew formula in `0funct0ry/homebrew-tap`; `release-extra.yml` for the signed and notarised dmg, `.deb`, `.rpm`, AppImage, static musl headless tarball, CycloneDX SBOM, winget manifests, the Homebrew cask and release notes taken from CHANGELOG.md (`scripts/release-notes.sh`); `docker.yml` and a `Dockerfile` publishing the headless build as `ghcr.io/0funct0ry/fauxfield` (workspace at `/workspace`); SHA-256 checksums and artifact attestations for everything. Opt-in update check (`check_for_updates`, off by default): status-bar notice, *Help: Check for Updates…* and `fauxfield version --check [--json]`; nothing is downloaded or installed. `fauxfield doctor` reports GPU backend, display server (Wayland/X11), Vulkan availability and the update-check state. `make dist` now runs cargo-dist (`make dist-local` keeps the plain tarball, `make dist-plan`, `make docker`). `RELEASING.md` holds the release checklist.
- Marketing site and documentation (M18): `site/` is now an Astro + Starlight project. The marketing page at `/` (hero with a live templated response, the Workspace-as-files section, features, agents, a comparison table that includes the rows Fauxfield loses, install tabs) and the docs at `/docs/` (Getting started, Guides, Reference, Recipes, Changelog) use One Light / One Dark tokens and self-hosted IBM Plex, with Pagefind search, per-page Open Graph images, and download links and a version label read from the latest release at build time. New pages: install, first mock, Workspace layout, Templating, CI usage and two Recipes. New generated page `reference/server-file.md` (`cargo xtask server-docs`, from the model's JSON Schema); every reference page is now generated and checked by `cargo xtask check`. `make site`, `make site-dev` and `make site-check`; `.github/workflows/site.yml` builds on pull requests and deploys to GitHub Pages from `main` and release tags. Docs pages moved to `site/src/content/docs/docs/` so they serve under `/docs/`. Help > Documentation and the About box now open the docs site. Lighthouse on the built site: performance 100 and accessibility 100 on `/`, 99 and 100 on a docs page.

### Changed
- The Inspector pretty-prints JSON, XML and HTML request and response bodies (syntax highlighted as before); the recording keeps the raw body.
- The Inspector "Variables in scope" and "Seed" sections fold and unfold from their headings (chevron; kept for the session).
- The workspace menu hides New server, Rename workspace and Close workspace while no workspace is open.
- Header editors (Route and Response) fill the available width. The Inspector header has an `x` button (hide the Inspector); the Traffic and Logs tabs of the bottom dock have a trash button (clear all, new action `clear_logs`). The Welcome screen and About box draw the marketing-site mark, and the packaging icons (macOS `.icns`, Linux `.png`, Windows `.ico`, master `packaging/icon/fauxfield.svg`) now match it; the `.deb`, `.rpm` and MSI install them.
- Route Headers sub-tab: header names and common values now complete as in the Response headers table (Up/Down, Enter/Tab or click, Esc).
- Header values (Route and Response) complete Tera: inside `{{ }}` or `{% %}` the cell offers context keys, `vars.*`, functions, filters and `fake` kinds, like the body editor; Tab or Enter inserts the choice and keeps the cell open.
- Route context menu in the sidebar gains **Copy as cURL** (server address, prefix and path, with the default Response's Rules satisfied). The Route tab's *Send test* button is now an icon-only **Copy as cURL** button; the palette action `copy_route_curl` replaces `send_test`.

- Header editors (Route and Response) show an inline error under a value that reads request data the sample request does not have (for example `request.headers["x-tenant"]`), with advice to use `| default(value=...)`, not only template syntax errors. The sample request used by the Preview now carries the common client headers (`accept`, `content-type`, `user-agent`, `authorization`, `x-request-id`).

- Response Actions tab on a Server without Datasets: **+ Add action** is dimmed and the empty state says why, with a **Create Dataset…** button, instead of a toast only.

### Removed
- *Send test* in the app (button, **Route: Send Test Request**, menu entry). `Cmd/Ctrl+Enter` now only opens a Quick Search result pinned (`picker_open_pinned`). The `send_test_request` MCP tool and `fauxfield` control API are unchanged.
- The per-Route *Sample…* request dialog (it did not work): Send test now fires the Route's own method and path.

- Callbacks and webhook simulation (M14): a Response may declare `[[routes.responses.callbacks]]` (`id`, `method`, `url`, `delay_ms`, `headers`, `body`, `retries`, `backoff_ms`, `timeout_ms`, `disabled`); after the body is sent each Callback waits its delay, renders `url`, `headers` and `body` as templates (`callback.body` for `hmac_sha256` signatures, `response.*` for the sent Response), sends over the proxy's hyper client with a timeout, and retries with doubling backoff on connection errors, timeouts and 5xx. - WebSocket mocking (M13): a `websocket` Route upgrades on the Server's own listener and runs in `echo`, `script` or `broadcast` mode. `[[routes.messages]]` send on `connect`, on an `interval` (`every = "500ms"`, `"5s"`, `"1m"`) or in reply to an incoming `message` matching `when` (a `body` rule whose `key` is a JSONPath); bodies are Tera templates with `connection.id` and `message.text` / `message.json`, text frames or base64 `binary = true`, optional `close_code`. Pings get pongs, close codes are echoed and every connection is closed with 1001 when the Server stops. A plain GET to a WebSocket Route answers 426; the 101 upgrade is a Traffic row. New diagnostics E102 to E107 and W093. A message `format` (`compact` by default, `pretty`, `raw`) controls how JSON bodies are sent; the editor has a Format JSON button, editor and preview sit side by side, and the Send box renders templates per recipient (`Engine::ws_send_rendered`). The Route tab has the mode, a messages editor with a rendered preview, live connections (Disconnect), the in/out timeline, and ad-hoc send to one or all clients; palette actions *Route: New WebSocket* and *WebSocket: Send Draft Message to All Clients*. `fauxfield ws list|log|send|disconnect` (all with `--json`), MCP tools `list_ws_connections`, `send_ws_message`, `disconnect_ws_client`, control methods `ws.*`.
